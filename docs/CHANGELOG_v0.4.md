# DriveMate 0.4：實測失敗案例修正

## 修正 1：試乘意圖優先辨識

收到「我想預約 EX30 試乘」時，以意圖判斷優先於一般車型資訊查詢，
引導至右側**模擬試乘預約**表單。前端會自動選擇有收錄的車型，但不會自動寫入資料庫。
使用者仍需輸入虛構暱稱、未來的模擬時間，並明確勾選「模擬」後提交。
本路由標示為 `booking_guidance`，**不是 LLM Tool Calling，也不是建立了真實預約**。
預約回廠保養走原本的 RAG，不會誤導至試乘表單。

## 修正 2：充電接頭安全題

EX30 充電線損壞或有碎屑時，Volvo 公開安全說明要求停止使用損壞充電線、
不得用工具清理充電線接頭，應聯絡授權維修中心或在充電站改用其他充電點。
當向量檢索已找到**明確含有上述警告**的文件段落時，後端直接使用受約束的
安全回覆樣板，防止小型模型把明確禁令答成「文件不足」。
找不到支持段落時不套用，仍照原先 RAG 流程處理。

資料來源參考：<https://www.volvocars.com/tw/support/car/ex30/article/47d2c97fd33effd3c0a8cc3718c999b7-663e525fd3355dadc0a8cc377cb86c78-8664b2fa77a7e089c0a8296870d1a409/>。

## 安裝

下載 `DriveMate_v0.4_patch.zip` 後，在專案根目錄 `unzip -o ... -d .`，
重啟 FastAPI 和前端。**沒有更改 RAG 知識庫 JSON，無須重新建立向量索引。**

## 測試

`python -m pytest -q backend/tests`

預期：預約試乘能引導表單、充電線安全問題能清楚提醒、原有車型/庫存/RAG 測試不退步。
